Linux Character Driver Geliştirme Raporu
1. Projenin Amacı

Bu çalışmada Linux işletim sistemi üzerinde çalışan basit bir Character Device Driver (Karakter Cihaz Sürücüsü) geliştirildi.

Amaç, kullanıcı alanında çalışan bir programın veya terminal komutlarının, yazdığımız özel bir Linux kernel modülü ile iletişim kurmasını sağlamaktı.

Geliştirilen sürücünün adı:

ahmet

olarak belirlendi.

Son durumda kullanıcı şu işlemleri yapabilir hale geldi:

echo "Merhaba Kernel" > /dev/ahmet

ile kernel tarafındaki sürücüye veri gönderebilir.

ve:

cat /dev/ahmet

ile kernel tarafından saklanan veriyi okuyabilir.

2. Linux Mimarisi: User Space ve Kernel Space

Linux işletim sistemi temel olarak iki önemli çalışma alanına ayrılır:

User Space (Kullanıcı Alanı)

Normal uygulamaların çalıştığı bölgedir.

Örnekler:

Terminal
Firefox
Python programları
C uygulamaları

Kullanıcı programları güvenlik sebebiyle doğrudan donanıma veya kernel belleğine erişemez.

Kernel Space (Çekirdek Alanı)

Linux çekirdeğinin çalıştığı bölgedir.

Kernel şunlardan sorumludur:

Donanım yönetimi
Bellek yönetimi
Process yönetimi
Dosya sistemi
Device driver'lar

Bir kullanıcı programı doğrudan donanıma erişemez.

Bunun yerine:

User Application
        |
        |
        ↓
Device File (/dev/ahmet)
        |
        |
        ↓
Kernel Driver
        |
        |
        ↓
Hardware

mantığı kullanılır.

Biz burada bu zincirin ortasındaki kernel driver kısmını geliştirdik.

3. Character Device Nedir?

Linux'ta cihazlar genel olarak ikiye ayrılır:

Character Device (Karakter Cihazı)

Veriyi karakter karakter veya akış şeklinde işler.

Örnek:

Klavye
Seri port
Sensörler
Basit iletişim cihazları

Bizim yaptığımız sürücü:

Character Device Driver

dır.

Block Device (Blok Cihaz)

Veriyi bloklar halinde işler.

Örnek:

HDD
SSD
USB disk
4. Kernel Module Nedir?

Linux kernel'e çalışma sırasında eklenebilen küçük programlara:

Kernel Module (Çekirdek Modülü)

denir.

Avantajı:

Kernel'i yeniden derlemeye gerek kalmadan yeni özellik ekleyebiliriz.

Örneğin:

Bir WiFi driver'ı veya ekran kartı driver'ı kernel modülü olabilir.

Bizim modülümüz:

ahmet.ko

dosyasıdır.

.ko

uzantısı:

Kernel Object

anlamına gelir.

5. İlk Adım: Kernel Module Oluşturma

Öncelikle Linux kernel modülü yazabilmek için gerekli başlık dosyalarını ekledik:

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>
#include <linux/device.h>

Bu dosyaların görevleri:

linux/module.h

Kernel modülü oluşturmak için gereklidir.

Şunları sağlar:

module_init()
module_exit()
MODULE_LICENSE()

gibi fonksiyonlar.

linux/fs.h

Dosya sistemi fonksiyonlarını sağlar.

Character device için:

file_operations

yapısı burada bulunur.

linux/cdev.h

Character device oluşturmak için kullanılır.

Bize:

struct cdev

yapısını sağlar.

linux/uaccess.h

User space ile kernel space arasında güvenli veri transferi için kullanılır.

Fonksiyonlarımız:

copy_to_user()

copy_from_user()
linux/device.h

Linux Device Model için kullanılır.

Şunları sağlar:

class_create()

device_create()
6. Device Number Oluşturma

Linux'ta her cihazın kendine ait bir numarası vardır.

Bunlar:

Major Number

Cihazın hangi driver tarafından yönetildiğini belirtir.

Örneğin:

510
Minor Number

Aynı driver altındaki cihazları ayırır.

Örneğin:

0

Biz bunu elle vermek yerine:

alloc_chrdev_region()

fonksiyonu ile kernel'den istedik.

Kod:

ret = alloc_chrdev_region(&dev_num,
                          0,
                          1,
                          "ahmet");

Burada:

&dev_num → cihaz numarasını buraya yaz
0 → başlangıç minor numarası
1 → kaç cihaz oluşturulacağı
"ahmet" → cihaz ismi

Kernel bize:

Major: 510
Minor: 0

verdi.

7. CDEV Oluşturma

Linux'ta aldığımız numarayı gerçek bir character device haline getirmemiz gerekir.

Bunun için:

static struct cdev ahmet_cdev;

tanımlandı.

Daha sonra:

cdev_init(&ahmet_cdev, &fops);

ile cihazımıza hangi fonksiyonların çalışacağını söyledik.

8. File Operations Yapısı

Linux cihazlarla iletişim kurarken dosya mantığını kullanır.

Örneğin:

cat /dev/ahmet

aslında kernel'e:

"Bu cihazın read fonksiyonunu çağır"

demektir.

Bu yüzden:

static const struct file_operations fops

oluşturduk.

İçine:

.open = ahmet_open,
.release = ahmet_release,
.read = ahmet_read,
.write = ahmet_write,

ekledik.

9. Open Fonksiyonu

Kullanıcı cihazı açınca çalışır.

Örneğin:

cat /dev/ahmet

başladığında:

ahmet_open()

çağrılır.

Kod:

pr_info("Device opened\n");

ile kernel loguna yazdırdık.

10. Write Fonksiyonu

Amaç:

User space'ten kernel'e veri almak.

Örneğin:

echo "Merhaba Kernel" > /dev/ahmet

çalışınca:

ahmet_write()

çağrılır.

Veriyi almak için:

copy_from_user()

kullandık.

Akış:

Terminal

"Merhaba Kernel"

      |
      ↓

copy_from_user()

      |
      ↓

Kernel buffer
11. Kernel Buffer Oluşturma

Veriyi saklamak için:

static char buffer[BUFFER_SIZE];

oluşturduk.

Boyutu:

#define BUFFER_SIZE 1024

yani:

1024 byte.

12. Read Fonksiyonu

Kullanıcı:

cat /dev/ahmet

dediğinde:

ahmet_read()

çalışır.

Kernel buffer içindeki veri:

copy_to_user()

ile kullanıcı alanına gönderilir.

Akış:

Kernel Buffer

      |
      ↓

copy_to_user()

      |
      ↓

Terminal
13. Linux Device Model Kullanılması

Mentörün istediği önemli noktalardan biri buydu.

Eski yöntemde:

mknod /dev/ahmet c 510 0

ile cihaz dosyasını elle oluşturabilirdik.

Ancak profesyonel Linux driver geliştirmede bu tercih edilmez.

Bunun yerine Linux Device Model kullanılır.

Class Oluşturma
ahmet_class = class_create("ahmet_class");

ile:

/sys/class/ahmet_class

oluşturulur.

Device Oluşturma
device_create(
    ahmet_class,
    NULL,
    dev_num,
    NULL,
    "ahmet"
);

ile gerçek cihaz oluşturulur.

Bu işlemden sonra:

udev servisi sayesinde:

/dev/ahmet

otomatik oluşur.

Yani artık:

insmod ahmet.ko

yeterlidir.

Elle:

mknod

yapmaya gerek yoktur.

14. Driver'ın Yüklenmesi

Derleme:

ahmet.ko

oluşturuldu.

Kernel'e yükleme:

sudo insmod ahmet.ko

lsmod | grep ahmet

çıktısı:

oldu.
